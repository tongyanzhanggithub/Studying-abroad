## 一、换机器后怎么跑起来

```bash
git clone https://github.com/tongyanzhanggithub/Studying-abroad.git
cd Studying-abroad
git checkout security-fixes-and-us-expansion   # ⚠️ 改动都在这个分支,不在 main

npm install
cp .env.example .env        # 按注释填 DATABASE_URL / AUTH_SECRET / CRON_SECRET

npx prisma generate
npm run db:push             # ⚠️ 本分支新增了两张表,必须 push(见第三节)
npm run db:seed
npm run data:import         # 院校项目数据(data/raw,已入版本管理)
npm run schools:import      # 已核实的目标校 + QS 排名(data/schools)

npm run check               # typecheck + 78 个单测 + 生产构建,应全绿
npm run dev
```

演示账号:`npm run admin:create` 建超管;`PHONE=13800138000 npm run demo:seed` 建带季票的学生。

> ⚠️ **本地 PGlite(`npm run db:start`)在本项目上很不稳**,单连接、强杀进程易损坏数据。
> 日常开发请装真实 Postgres 或用 Docker,别用它。

## 二、这个分支做了什么(18 个 commit)

按类别,不按时间:

### 安全
- **材料下载 IDOR**:顾问原可凭 id 取任意学生的护照/身份证(`role !== 'data_entry'` 把 advisor 也算成 staff)
- **mock 支付零元购**:生产环境拿到 outTradeNo 点一下就白拿季票 → 加 `ALLOW_MOCK_PAYMENT` 开关,默认拒绝
- **后台 JWT 不回查库**:停用/降权的管理员在 token 过期前(最长 30 天)仍有权限
- **SSRF 加固**:undici dispatcher 在实际建连 IP 上校验(防 DNS rebinding)、重写 IPv6 私网判定、抓取改流式限量
- **依赖漏洞**:sharp/postcss 3 个 high 清零(⚠️ 不能用 `npm audit fix` —— 它会把 next 降到 9.3.3)
- 验证码改 CSPRNG、AUTH_SECRET 强度校验、生产强制独立 CRON_SECRET、cron 密钥恒定时间比较

### 资金正确性
- **支付履约幂等**:改事务内原子抢锁(微信会毫秒级并发重投)
- **退款幂等**:`executeRefund` 抢锁 + 恒定 `outRefundNo` + 渠道失败回滚
- **异议判退成死胡同**:判退只置 `refunding`,而唯一退款入口运营够不到 → 订单永久卡死
- **到期日跨月溢出**:`setMonth` 让 1/31 + 1 月 = 3/3,每次续费白送 1~3 天
- **卡死的退款单**:`refunding` 在后台两个 tab 都不可见且无 UI 能推进

### 数据与合规
- **数据不出境做成代码约束**(`src/lib/llm/region-guard.ts`):启动自检 + 运行时双重校验。
  ⚠️ 运行时那道是关键 —— 后台「AI 设置」页能把 key 存进数据库**覆盖 .env**,绕过启动自检
- **重新导入不再抹掉人工核对成果**(原 update 分支无条件打回 `ai_collected`)
- **采集防编造**:evidence 必须真实出现在原文中
- **注销账号删存储文件**(PIPL 删除权;此前护照密文永久残留)
- 地区闸门补漏、零容忍院校定稿死锁

### 用户内容
- **文书自动保存丢内容**:无 `.catch()` 且不看返回值 → 失败却显示「已保存」,用户接着写、关页面全没。
  全项目唯一会永久丢失用户创作的路径
- **AI 调用崩页带走未保存正文** → `completeSafe` 统一在服务端 catch
- **onboarding 失败白干**(刚付完钱那一屏)

### 新增功能
- 站内消息中心 `/app/notifications`(通知渠道要资质,这是当前唯一能兑现「截止提醒」承诺的方式)
- 后台用户管理 `/admin/users`(此前客服每个诉求都要改数据库)
- 系统健康页 `/admin/health` + cron 心跳(cron 静默失效此前零信号)
- 开票申请 `/admin/invoices`(定价页承诺了但功能不存在)
- 结算打款留痕 + CSV 导出
- 扩展美国(Region 加 `US`)

### 工程
- **vitest + 78 个单测 + GitHub Actions CI**(此前零测试零 CI)
- **自检脚本生产护栏**:`verify-settlement.ts` 会 `deleteMany` 手机号 `1390009*` 的用户,
  而这是真实号段。⚠️ 第一版护栏用黑名单,对本项目 `localhost:5432` 的实际部署**完全失效**,
  已改成默认拒绝(需显式 `ALLOW_DESTRUCTIVE_SELFTEST=true`)

## 三、部署前必读的坑

1. **两张新表**:`invoice_requests`、`settlement_payouts` —— 部署时 `prisma db push` 会创建。
   项目目前**没有 migrations 目录**,用的是 `db push`。收真钱前建议引入 `prisma migrate`,
   否则线上 schema 变更无版本、无回滚。
2. **`ali-oss` 不在 package.json**:`storage/oss.ts` 用动态 import。切 OSS 那天手动装能成功,
   但**下一次 `deploy.sh` 跑 `npm ci` 会把它删掉**,材料上传当场全挂。
3. **CI 已启用**:推分支会触发。本地每步验证过,但环境可能有差异,红了看 Actions 页面。
4. **服务器地域**:`deploy/README.md` 里的 `8.208.125.209` 在阿里云**国际站**段,
   无法 ICP 备案、不满足数据境内要求。生产必须在华东/华北/华南重开。

| 事项 | 卡在哪 |
|---|---|
| 注销账号会**级联删除支付与服务订单** | `Payment`/`ServiceOrder` 对 User 是 `onDelete: Cascade`,与代码注释「财税留存:支付记录解绑而非删除」和隐私政策承诺矛盾。修法有软删/匿名化 vs SetNull 两种,**影响 PIPL 口径** |
| `coreModuleUseCount` **恒为 0**(3 处读 0 处写) | 退款规则「7天内且使用<3次全退」退化成**无条件全退**。需定义哪些动作算「核心模块使用」 |

| 院校 3-4 级分档谁算哪级 | 编辑判断,代码只提供了 t1~t4 下拉 |
| 敏感材料留存期限 | 护照/身份证留多久、到期删文件还是连记录一起删 |
| 客服怎么承接 | 全站 5+ 处写着「联系客服」,但站上没有任何联系方式 |
