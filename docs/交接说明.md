## 一、换机器后怎么跑起来

```bash
git clone https://github.com/tongyanzhanggithub/Studying-abroad.git
cd Studying-abroad
git checkout security-fixes-and-us-expansion   # ⚠️ 改动都在这个分支,不在 main

npm install
cp .env.example .env        # 按注释填 DATABASE_URL / AUTH_SECRET / CRON_SECRET

npx prisma generate
npm run db:push
npm run db:seed
npm run data:import         # 院校项目数据(data/raw,已入版本管理)
npm run schools:import      # 已核实的目标校 + QS 排名(data/schools)

npm run check               # typecheck + 564 个单测 + 生产构建,应全绿
npm run dev
```

演示账号:`npm run admin:create` 建超管;`PHONE=13800138000 npm run demo:seed` 建带季票的学生。

### 两条会浪费你半小时的坑

**① 别在应用跑着的时候执行 `npm run check` / `npm run build`。**
它们和 `next dev` 共用 `.next` 目录,构建会覆盖开发服务器的 chunk,页面报
`__webpack_modules__[moduleId] is not a function`。要跑构建先停服务,跑完 `rm -rf .next` 再起。

**② 本地 PGlite(`npm run db:start`)在本项目上很不稳。**
它**每个进程只接受一次客户端连接** —— 开发服务器占着的时候,任何脚本都连不上;
强杀进程还容易损坏数据。这个会话里它卡死过六七次。
**日常开发请装真实 Postgres 或用 Docker。**

卡死时的处理:

```bash
netstat -ano | grep ":5433.*LISTENING"
```

拿到 PID 后 `taskkill //F //PID <pid>`,再 `npx tsx scripts/db-local.ts`。

## 二、这个分支做了什么

按类别,不按时间。

### 安全(三轮,最重要)

| 修的 | 说明 |
|---|---|
| SSRF | `isPrivateIp` 漏掉展开的 IPv6 环回和十六进制映射 IPv4;改成在**实际建连 IP** 上校验(防 DNS rebinding) |
| 开放重定向 | `/login?next=//evil.com` 登录后跳站外。要挡的不止 `https://` —— `//`、`/\`、`/%2f%2f` 浏览器都当站外 |
| 免费评估无限流 | 全站唯一**不需登录**、又写库又跑匹配计算的入口。一个循环就能灌爆 Lead 表 + 算满 2 核机器 |
| 埋点写入无上限 | `trackShare('A'.repeat(1e7))` = 一行 10 MB。封顶做在 `track()` 入口,覆盖所有调用方 |
| 订单号用 `Math.random` | V8 是 xorshift128+,观察几个输出可反推内部状态。改 CSPRNG + Crockford Base32 |
| 模拟支付缺归属校验 | action 和 page **两处**都缺(第一轮只修了一半) |
| 无 CSP | 上了带 nonce 的完整策略。`base-uri` / `form-action` / `object-src` 是真正挡攻击的几条 |
| 改密码不失效其他设备 | 加 `sessionVersion`,签进 JWT,`getCurrentUser` 里比对 |
| 支付幂等 | 原子条件更新 + 常量 `outRefundNo`,渠道失败回滚 |
| 材料文件 IDOR | 按角色 + 交付人归属校验,不再用 `role !== 'data_entry'` 粗判 |

### 数据正确性

- **时区**:`toISOString()` 永远是 UTC —— AI 配额在北京时间**早 8 点**才重置;结算月份口径随系统时区漂。部署侧 `TZ=Asia/Shanghai` + 代码改用本地日期,两边都要改
- **注销账号**:钱的凭据(Payment / Subscription / ServiceOrder)解绑保留,个人数据真删。此前 `Lead` 根本没被删 —— 手机号和评估结果一直留在库里
- **退款规则**:`coreModuleUseCount` 全项目只读不写、恒为 0,`0 < 3` 恒真 → 「少于 3 次」从未生效。已改为**无条件 7 天全退**并同步四处文案
- 到期日 `setMonth` 跨月溢出;排名双写不一致;文书自动保存每次停顿存一份全文

### 新增模块(四个)

| 模块 | 相对行业模板做了什么 |
|---|---|
| **材料中心** 扩充 | 静态清单 → 按学历状态**互斥分支**;份数/找谁办变字段;加分项不计入完成度 |
| **素材库** `/app/story` | 每篇文书填一次 → **答一次各校通用**;删掉父母职业等无关信息 |
| **推荐人** `/app/referees` | 以推荐人口吻写信 → **以自己口吻整理事实清单**,信由推荐人自己写 |
| **网申信息** `/app/profile` | 自己对日期找空档 → **系统算**;砍掉一半敏感字段 |

### 性能

首页跨请求缓存、看板 `groupBy` 取代整表扫描、截止提醒 cron 日期下推到 SQL、
首屏图 1.9 MB → 125 KB(WebP)、材料重算改一次事务。

### 合规

数据保留期清理 cron(PIPL 第 19 条)、数据导出补齐新模型、
`region-guard` 把「数据不出境」变成代码约束。

## 三、部署前必读

### ⚠️ 这次有一个破坏性 schema 变更

`deploy.sh` 里的 `npx prisma db push` 检测到删列会**要求交互确认**,而脚本是非交互跑的
—— 会直接报错退出,卡在依赖装完、构建没开始的状态。

**先手动删掉这一列**(值恒为 0,无信息损失):

```bash
sudo -u postgres psql compass -c 'ALTER TABLE subscriptions DROP COLUMN IF EXISTS core_module_use_count;'
```

其余变更都是安全的:新增 4 张表(`StoryAnswer` / `Referee` / `RefereeAnswer` / `TimelineEntry`)、
加列(都有默认值)、三张钱相关表的 `user_id` 放宽为可空。

### 部署步骤

```bash
cd /opt/compass && sudo -u postgres pg_dump compass | gzip > /var/backups/compass-预部署-$(date +%F-%H%M).sql.gz
```

```bash
cd /opt/compass && git fetch origin && git checkout security-fixes-and-us-expansion && git pull
```

```bash
cd /opt/compass && sudo bash deploy/deploy.sh
```

时区改的是 systemd 单元文件,要单独生效:

```bash
sudo timedatectl set-timezone Asia/Shanghai && sudo systemctl daemon-reload && sudo systemctl restart compass
```

### 部署后必验四条

1. **首页不白屏** —— 这次上了完整 CSP,配错就是整站白屏,这是最大风险
2. **F12 控制台无红色 `Refused to...`** —— 有就是 CSP 误伤,立刻回滚 `src/middleware.ts`
3. `date` 输出是北京时间
4. `/admin/health` 出现第三行「数据保留期清理」(首次显示异常是正常的)

### 其他

- `data/raw/*.json` 在 `.gitignore` 里,`git pull` 不带院校数据,需要时 `scp` 上传
- 进程内限流(`lib/rate-limit.ts`、采集礼貌层)依赖**单进程**部署。上多实例要换 Redis

### ⚠️ 当前这台服务器是**测试机**,接真实用户前必须换

| | |
|---|---|
| 公网 IP | `8.208.125.209`(阿里云**国际站**段) |
| 地域 | **英国(伦敦)** |
| 镜像 | Ubuntu 24.04 |
| 定位 | **仅供测试**,用户 2026-08-16 确认 |

两个限制,都不是配置能解决的:

1. **数据在境外。** 这个项目把「数据不出境」当硬约束 —— `lib/llm/region-guard.ts`
   把它写成了代码约束并配了测试。但那只管住了 LLM 端点,管不住服务器本身。
   应用会存学生的**护照与身份证扫描件**,放在伦敦属于个人信息出境。
   现在库里没有真实学生数据,所以没问题;**一旦开始接真实用户就必须先迁到境内实例**。
2. **国际站 IP 拿不到 ICP 备案**,域名绑不了,只能用 IP 访问。
   连带的:没有 HTTPS → 会话 cookie 不带 Secure(见 auth/session.ts 的注释),
   明文传输,同网络的人可截获。测试期可接受,对外不行。

迁移时要一起带走的:`.env`(含 AUTH_SECRET / CRON_SECRET,丢了所有人都得重新登录)、
`uploads/`(学生上传的材料)、Postgres 数据库。代码和 `data/schools`、`data/corrections`
都在 git 里,`data/raw` 要单独 scp。

## 四、已经做过的决策(别再重新讨论)

| 决策 | 结论 | 理由 |
|---|---|---|
| 退款规则 | **无条件 7 天全退** | 分散的计数器正是它腐烂成死字段的原因;价位 ¥30–306,薅的收益很小;无条件本身是更好的卖点 |
| 注销时的钱 | 三张表**一起解绑保留** | `Payment` 没有 subject 字段,只留它就说不出卖了什么;`ServiceOrder` 还挂着交付人分成凭据 |
| 推荐信 | **不代写、不协助代签** | 行业模板让学生「以推荐人口吻」写,那是学术不诚信;我们只产出给推荐人的事实清单 |
| 素材库收集范围 | **不问父母职业/收入** | 对硕士 PS 价值很低,而它是明确的个人信息 |
| 网申信息收集范围 | **不收身份证号、监护人证件** | 那是签证代办的需求,不该带进学生自助工具;监护人信息学生无权代为同意 |
| AI 文案 | **跟着配置自动变** | 靠人记得改不可靠 —— 接上模型没人会想起来加回去,换回 mock 更不会想起来撤 |
| 爬取范围 | 本科+硕士、英国全部大学 | 用户 2026-08-06 决定。**但见第六节的前置条件** |

## 五、还没做的

### 只能你来(外部依赖)

营业执照 → ICP 备案 → 微信商户号 → 小程序资质;境内 ECS/RDS;短信签名报备;
**国内模型 API key**;律师过法律文本;310 个项目的人工核对。

### 截止日口径(2026-08-19 已定)

**倒计时 = 申请通道关闭那一天。** `Program.finalDeadline` 只认
`final_deadline`,不拿轮次日期顶替;拿不到就置 null,前端显示
「截止日待公布」,详情页照样列轮次表。

改之前它取的是「所有已知日期里最早的未来日期」,而那批日期包含各轮次 ——
拿 `data/raw` 的 310 个项目实测(以 2026-09-01 为今天):

| | |
|---|---|
| 不变 | 278 |
| **倒计时推后** | **31** —— 原来指向更早的轮次 |
| 失去倒计时 | 1(NUS 供应链,最终截止日缺失) |

最夸张的是 UBC 的 Master of Management:原来倒计时到 `2026-10-06`,
而申请通道 `2027-05-04` 才关 —— 早了七个月,学生会以为自己错过了。

规则写在 `src/lib/programs/deadline-sanitize.ts`,用例在同名 test 里。

### 批量导入不发变更通知(待定)

`data:import` 和 `fix:deadlines` 改截止日时,既不写 `programChangeLog`
也不调 `notifyProgramChange`,而仪表盘上写着「学校改要求也会第一时间告诉你」。
接上通知是个大动作 —— 一次重新采集可能触发成百上千条短信,需要先想清楚
怎么区分「院校真的改了」和「我们自己采错了重采」(后台单条编辑那里
已经有这个区分,默认不推送)。

### 代码侧可做

- 结算月份边界用本地时区(TZ 已钉死,但边界逻辑值得再审一遍)
- 页脚 ICP 号 + 公司主体 + 客服联系方式
- 全额退款的审批流(建议等微信支付接入后再做)
- 完整 CSP 的 `style-src` 仍有 `unsafe-inline`(Tailwind 注入内联样式,暂时收不紧)

## 六、爬取项目的现状与前置条件

用户已决定范围:**本科 + 硕士、英国全部大学**。但目前**开不了工**,卡在两个地方。

### 已完成:抓取礼貌层(`lib/collect/politeness.ts`)

放量前绕不过去的一步 —— 大学官网普遍有 WAF,连续高频请求会封掉**服务器出口 IP**。
已实现 robots.txt 遵守 + 按站点队列限速,并接到 `fetchPageText` 里(在 SSRF 校验之后、
真正发请求之前)。

两个容易写错的点已经处理并有测试钉住:
- robots **只取最具体的 User-agent 分组**,不能把所有分组的规则并起来
- 限速用**队列**,不是「距上次多久」—— 后者在并发下会一起放行,形同虚设

### 卡口一:模型 key(只有你能填)

`lib/collect/extract.ts:245` 依赖 `getLlmProvider()`,而 `LLM_PROVIDER=mock`。
「按申请要求爬取」里最值钱的部分(学历要求、雅思总分和小分、GMAT/GRE、学费、截止日)
全靠模型从网页里抽。没有它只能拿到课程名和链接。

配置见 `deploy/README.md` 的「AI 文书还没接模型」一节,三行 + 一把 key。

### 卡口二:本科是产品改造,不是爬取任务

`Program` 表**没有学位层次字段**。评估引擎的定位规则、材料模板(在读证明/推荐信/PS)、
首页文案 —— 全都按授课型硕士建的。

本科逻辑完全不同:A-level/IB 成绩体系、UCAS 统一申请、个人陈述只写一份、5 个志愿上限。
要做得先动 schema 和评估引擎,**改造期间现有硕士功能会受影响**。

### ⚠️ 规模与产品规则的冲突(最关键)

英国约 130–165 所大学,本科课程约 14 万、授课型硕士约 4–7 万,**合计 15 万+**。

但你自己的产品规则是:
- 新导入一律标 `ai_collected`(待核对)
- 地区闸门要求**核对率 ≥ 90%** 才能开放
- 看板红线:未核对占比 >10% 就该暂停投放

**15 万条未核对数据进库 = 未核对率 99.8%,英国永远开不了,前台一条都不显示。**
等于花几天时间和几千块钱,换来零用户可见价值 + 一个再也绿不了的告警。

现在库里 310 条是手工整理的 —— 那个数量级才可能被人核对完。

**所以真正的问题不是「能不能爬 15 万条」,是「这 90% 的核对谁来做」。**

### 建议的下一步

先跑**一所大学**的完整流程,量出三个数:每条的抽取成本、抽取准确率、人工核对一条要多久。
第三个最关键 —— 它决定了整个范围可不可行。拿到数再决定放量多少。

### 测试怎么读

564 个单测,其中相当一部分是**守卫测试** —— 不验功能,验「某个容易悄悄退化的约定还在」。
每一条都在写的时候反向验证过(改坏代码,确认它转红)。典型的几个:

| 文件 | 钉住什么 |
|---|---|
| `lib/refund-policy.test.ts` | 代码怎么算 ↔ 页面怎么说,不许再出现「少于 3 次」 |
| `lib/account-deletion.test.ts` | 钱的表必须 SetNull,个人数据必须 Cascade |
| `lib/data-export.test.ts` | 新加的用户数据模型必须进导出(否则转红逼你做决定) |
| `lib/cache-tags.test.ts` | 改数据的 action 必须让缓存失效 |
| `lib/randomness.test.ts` | 安全相关标识符不许用 `Math.random` |
| `lib/seo.test.ts` | 页面不许手写 `openGraph`(会覆盖掉 og:image) |

> ⚠️ 写这类源码扫描测试时注意:**注释里往往正好写着那个反例**。
> 这个会话里被骗过四次。统一用 `lib/source-scan.ts` 的 `codeOnly()` 去掉注释行。
